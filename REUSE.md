# Reuse Inventory

**Last reviewed:** 2026-10-21  
**Project:** [Boonta Reborn 88](https://github.com/Master-Chiken/boonta-reborn-88)

This inventory tracks tools, public research, and potential third-party dependencies that may help avoid duplicated work. It separates **using a tool**, **studying a project as a technical reference**, and **copying or redistributing code or data**. These are different permissions.

A project's appearance in this table is **not** approval to copy its code, binaries, models, textures, sounds, or other data into Boonta. The status describes our evaluation, not the maturity of the upstream project.

## Reuse rules for Boonta

1. **Research is not a code license.** Cite the exact repository, revision, file, and platform; independently implement behavior when appropriate instead of copying source.
2. **Check exact licensing before integration.** Inspect the relevant file, its copyright header, upstream LICENSE, dependencies, generated outputs, and distribution requirements. If uncertain, keep the status **To verify** and do not copy.
3. **Do not change Boonta's license accidentally.** The current repository LICENSE is MIT. GPL/AGPL imports need an explicit compatibility and distribution review before any code is copied; this table is not legal advice.
4. **Never publish commercial game content.** Do not commit ROMs, disc images, BIOS files, extracted models, textures, sounds, tracks, geometry, or other proprietary data. Do not place them in prompts, issues, CI artifacts, or hosted tools.
5. **Do not mistake format clues for compatibility proof.** Matching filenames, strings, or apparent layouts do not prove that PC, Dreamcast, N64, GameCube, and Wii data structures are identical.
6. **Test small and separately.** Before adopting an external library, establish license provenance and platform compatibility, then run a minimal synthetic fixture or a separate isolated proof of concept. Do not integrate an experimental renderer merely because its API resembles OpenGL.
7. **Record exactly what happened.** Mark a component **Tested** only when a specific test was actually run and its result is recorded. A README, build recipe, or CI badge is not evidence that Boonta has tested the component.

## Open verification items

- **OpenGX:** verify project-wide and file-level licensing/provenance; determine whether required rendering calls are available; build and benchmark a separate minimal test before discussing integration.
- **SW_RACER_RE:** re-check the exact file/revision before any source reuse; maintain strict separation between PC evidence and console behavior.
- **Sw_Racer:** resolve README versus License.txt licensing conflict and audit dependencies.
- **swe1r-tools:** confirm the exact script and game version for each needed format; check whether the required operation is supported by the public version.
- **SWE1R-Mods:** verify each script's license/authorship and the rights of any associated mod data.
- **decomp.anything:** determine whether a free-only, privacy-safe, browser-compatible workflow is practical; keep it optional until tested.
- **Dreamcast formats:** compare local PC and Dreamcast block headers, offset tables, dimensions/records, and parser behavior. Similar block filenames alone are inconclusive.
- **N64 / GameCube / Wii:** do not infer console layout or behavior from PC code. Record separate evidence and unresolved questions.
