# Step 102 source provenance review

Date of original review: 2026-10-14

Last reviewed: 2026-10-15. The hold remains until the author/origin and redistribution terms are established.

## Current decision: HOLD

The supplied 123-file source-only bundle has no top-level LICENSE/COPYING file. The inspected source file `source/racer_physics.c` begins with a functional description but no copyright, author, SPDX identifier, or redistribution license header. This is not proof that the code is unlicensed; it means the supplied files alone do not establish the terms under which the code may be published in this public repository.

## Required before public import

For the bundle author / project maintainer to resolve:

- Identify the author(s) and the repository or source of each code family.
- State whether each file was independently authored, generated, or adapted from an upstream project.
- Add an explicit repository license only if the rights holder can grant it; do not assume that adding a LICENSE file retroactively clears third-party code.
- Preserve required notices for any dependencies and confirm compatibility with public redistribution.
- Review generated data separately. In particular, `source/track_centerline.generated.h` contradicts the bundle README's exclusion statement and remains on HOLD.
- Remove generated bytecode such as `tests/__pycache__/*.pyc` from any proposed import.

## Candidate review order

1. Readable host tests and mock headers: review test fixtures and any copied code, then import only after licensing is established.
2. Build scripts and Makefile: review command sources, downloaded dependencies, and license notices.
3. C source and headers: review each file's origin and derivation; similar naming or passing tests does not prove originality.
4. Procedural demo track CSVs: verify that they are synthetic/original and do not encode extracted or mod-derived course geometry.
5. Generated headers and all media/geometry: keep excluded until inputs and permissions are documented.

## What current tests establish

The bundle's reported 32 shell checks and 5 Python policy tests establish only that the extracted bundle passed those host checks in the earlier temporary environment. They do not establish authorship, legal redistribution permission, CI execution, a native GameCube build, or gameplay.

## Safe next action

Obtain a clear provenance/license statement from the bundle's author or reconstruct the code from independently verifiable original sources. Until then, do not bulk-import the bundle into the public repository. Continue improving the repository's build pipeline and documentation without copying uncertain code.
