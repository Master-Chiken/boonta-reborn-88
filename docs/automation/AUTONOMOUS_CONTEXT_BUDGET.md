# Autonomous provider context budget

This is the shared context and execution budget for scheduled Gemini, OpenRouter Free and Groq Free cycles.

## Non-negotiable cycle budget

- One model provider invocation at most per Boonta Autonomous Loop run. If a provider fails, do not call the next provider in that same run. After its persistent same-day cooldown is recorded, a trusted `repository_dispatch` starts a separate run; that run must re-read the cooldown and task state before advancing. The four daily scheduled runs remain the recovery backstop if dispatch delivery fails.
- Provider order: Gemini first; OpenRouter Free only in a later, cooldown-gated run when Gemini is skipped; Groq Free only in a later, cooldown-gated run when both Gemini and OpenRouter are skipped. A trusted internal dispatch can start that later run immediately; it never bypasses the cooldown preflight.
- A successful preflight is configuration evidence, not model execution or project progress. A run is engineering progress only when a provider invocation completed and its report is validated against a new or advanced open PR at the exact current head SHA.
- Never use a paid route, billing fallback, additional provider, or secret rotation to bypass a Free-tier quota. The project budget remains €0.

## Context and tool limits

- Start with the owner-approved workflow brief and `docs/automation/task-ledger-summary.json`. A read-only task-eligibility preflight must confirm exactly one eligible task before any provider is launched. Read the required project/provenance policies once; then read only files directly needed for the selected task.
- Keep newly retrieved repository/issue text below **1,500 tokens per cycle**. Keep full issue bodies and comment histories for #156, #226 and #279 out of provider context. Do not enumerate all PRs/branches or fetch attachments, images, media, binaries, ROMs, disc images, BIOS, or the approximately 452 KB route dossier.
- Do not fetch the full `docs/automation/task-ledger.json` for task selection. Use the compact summary; read a narrow task record only when a justified ledger update is required.
- The global eligibility preflight rejects malformed/ambiguous task ledgers, multiple active tasks, or an active task that already has a PR/head. It also performs a read-only, single-page open-PR query (100 items maximum) and rejects a task when any open PR body contains its exact `BOONTA_TASK_ID` marker. If the 100-item ceiling is reached, the preflight fails closed rather than risk missing an in-flight task PR. This prevents a second provider cycle from opening a duplicate while the first task PR is under review. The only blocked-task exception is the explicitly tracked post-cooldown activation bootstrap, and all three providers share the same `task_ready` gate. The bounded autonomous provider route does not resume or push to an existing task PR. If preflight finds an open PR for the selected task, it blocks provider invocation until that PR is reviewed/merged or the owner updates the task state. This avoids giving a model any in-place PR branch writer; the only autonomous delivery path is one new proposal, verified against the exact base and trusted main policy, followed by a workflow-owned non-auto-merged PR. New-task capacity is capped at three open PRs **per target branch**; `main` and `dev` are counted separately so unrelated work on one platform branch cannot starve a task on the other, while neither branch can exceed the same cap.
- Gemini CLI: pin the verified `0.67.0` release; exactly 1 attempt per invocation, automatic fetch-error retries disabled and maximum 3 session turns. Interactive requests retain their separately reviewed GitHub tools, but autonomous mode disables Gemini core filesystem tools and exposes only a local, one-use MCP reader plus one local patch-proposal tool. The model receives only the exact bounded task context and owner-approved target-branch excerpts; no GitHub token or remote writer is available to the model. The workflow-owned publisher validates the proposal in an isolated worktree, runs fixed tests and then publishes a non-auto-merged PR. Actions diagnostics remain limited to exact PR-head CI and failed-job logs.
- OpenRouter Free: OpenCode v1.19.5, maximum 8 build steps. Before inference, the workflow writes a task-bound `.gemini/context.json` from the verified context builder; the MCP validates its identity and returns only a SHA-256 digest of the already supplied context to avoid duplicate token payload. Autonomous mode exposes only the local `boonta` MCP server with `read_approved_sources` and `submit_patch_proposal`; it receives no GitHub token, GitHub MCP server or `push_files`. The local reader accepts 1–5 exact task paths and 1–10 exact line ranges, at most 80 lines per range and 240 lines total; source files are capped at 96 KiB each, aggregate source bytes at 256 KiB, and the proposal diff at 32 KiB. The workflow-owned verifier runs the mandatory tests in an isolated detached worktree, rechecks the trusted main policy and creates a non-auto-merged PR only after verification. Keep `OPENCODE_EXPERIMENTAL_CODE_MODE=false`, deny shell/filesystem tools and Task subagents, retain the 7,000-character prompt ceiling and 180-second hard timeout. The watchdog stops on the first explicit provider refusal and cleans up the process group on hard-timeout or runner cancellation. Before inference, the GET-only key preflight requires at least 8 remaining daily Free requests; the quota reserve is not a guarantee of cycle completion.
- The branch automation self-test executes both the static provider-handoff contract checker and the production OpenRouter watchdog heredoc using a local fake `opencode` process. Runtime cases verify first-refusal HTTP 429 handling, descendant-process termination, normal project output without false positives, SIGTERM cleanup and preservation of the captured report. These tests are offline and do not consume provider quota.
- Groq Free: OpenCode v1.19.5, **two bounded tool steps** (one source read and one patch proposal), 3,700 context tokens and 256 output tokens (7,912 nominal input/output tokens across two iterations, below the observed 8,000 TPM ceiling). The preloaded context is deliberately reduced to 1,400 characters total (maximum 1,000 task-context characters, three criteria, 80-character next action and 500 source-excerpt characters); the complete source excerpts arrive once through the local MCP reader. This keeps the measured 10,181-character compacted MCP result plus the 1,400-character preloaded context, fixed prompt and same-run facts below the 3,650-token pre-inference gate with a small safety margin. Before inference, the workflow writes a task-bound `.gemini/context.json`; the MCP verifies it and returns only a SHA-256 digest rather than duplicating the supplied context. The preflight estimates the compacted one-shot MCP source payload before inference; the workflow rejects the request when prompt plus source payload exceeds 3,650 estimated input tokens, leaving context headroom. C/C++ excerpts omit comments and blank lines while preserving string literals and original requested range boundaries; the same compaction logic is used by the preparation estimate and local MCP reader. The build agent requests temperature 0.2 and the model explicitly advertises temperature support; no retry is introduced. Autonomous mode exposes only the local `boonta` proposal MCP with the same 1–5 path, 1–10 range, 80-line per-range and 240-line aggregate limits; the model receives no GitHub token, GitHub MCP server or `push_files`. The workflow-owned verifier runs the fixed tests and publishes a non-auto-merged PR only after exact-path/base validation. Keep `OPENCODE_EXPERIMENTAL_CODE_MODE=false`, deny shell/filesystem tools and Task subagents, retain the 5,500-character prompt ceiling and 90-second watchdog; stop on the first TPM, HTTP 429, HTTP 401 or Free-quota refusal. No paid route or billing change is allowed.
- The autonomous loop snapshots only currently open PR heads and records a timestamp. A cycle-fresh report must cite a PR created after that snapshot or an existing open PR advanced after it; reopening an older closed PR is not progress.
- No model may write the repository. The local agent tools can read one bounded set of task-approved source excerpts and stage one unified-diff proposal in `RUNNER_TEMP`; only the workflow-owned verifier/publisher receives the scoped GitHub token. It revalidates trusted policy, applies the patch in a detached worktree, runs fixed tests and creates a PR requiring independent human review. Never merge, auto-merge, force-push or write protected branches.
- Do not reread the same file, call broad search/list operations or retry unavailable tools. Keep tasks small enough for the per-provider turn/step budget.

## Failure handling
- Cooldown preflight reads only issue #226 comments updated since 00:00 UTC on the current day (`since`), then verifies the embedded UTC date. Keep this bounded query in the global preflight and every provider-specific cooldown guard; the failure-recording step may still locate/update the persistent marker.


- **503 / temporary unavailability:** Gemini makes one model attempt only; after a 503 or TPM refusal, the invocation fails closed and its cooldown is persisted. The workflow then dispatches a separate run; fresh preflight should select OpenRouter Free immediately if its own cooldown is clear. If dispatch delivery fails, the next scheduled or owner-manual run is the backstop. Network `fetch failed` retries are disabled.
- **429 / TPM, context-size or request-too-large:** stop immediately, do not repeat the same request, and reduce the prompt/retrieved context/tool surface before the next attempt.
- **Daily Free quota or reserve insufficient:** do not call inference; wait for the next UTC day. OpenRouter preflight requires a reserve equal to its maximum configured build steps (currently 8), rather than starting with only 1–7 requests left. The API reports the counter on a UTC-day basis, and failed attempts count toward the cap. Never add credits or use a paid route.
- **Authentication or Free-tier attestation failure:** stop before inference. Do not ask for a new key when the same-run authentication already succeeded.
- If a timeout terminates a provider, treat the invocation as failed and respect its cooldown. A successful workflow preflight or cooldown check never counts as a model call.

- **Valid BLOCKED report:** do not mark the provider as failed. Persist a separate task-level UTC-day backoff marker so scheduled cycles do not spend another model call repeating the same blocked task. A validated PROGRESS report clears that marker. Owner-authorized manual dispatch or a qualifying main-branch push can re-evaluate earlier; the next UTC day also rechecks automatically.

## Reverse-engineering and provenance

Before implementation, inspect existing Boonta source, generated outputs, exporters, parsers, fixtures, tests, docs and directly related PRs. Prefer DISCOVER → VERIFY → EXTRACT/CONVERT/REUSE → INTEGRATE → TEST. Record exact source revision, platform/version, license/provenance, recovery decision and unknowns. Keep PC, N64, Dreamcast and GameCube/Wii behavior separate. Never send commercial game data or unclear-provenance material to hosted agents or public GitHub.

## Task-scoped source reads

Each executable task may declare 1–5 exact repository-relative text paths and 1–10 exact line ranges in the canonical ledger. Every listed path must be covered by at least one valid range; each range is at most 80 lines and the aggregate is at most 240 lines. CI validates that files exist, are safe UTF-8 text, fit the byte budget and contain every configured line. The context builder and local MCP reader fail closed when source excerpts are missing, malformed, out of bounds, repeated, over budget or empty; they never label an empty excerpt as ready. Gemini, OpenRouter and Groq autonomous models use the same bounded local reader and proposal-only writer. No provider may enumerate directories, guess paths, access unapproved paths, create branches/PRs or reread the protected canonical ledger/summary.

## Source of truth

The owner-approved workflow brief and compact task summary identify the bounded task. GitHub is authoritative for live PR state, exact head SHAs and CI evidence. If the task cannot proceed safely within this budget, stop with a specific BLOCKED report and one concrete next action; do not create empty branches/PRs or invent work.

All clean-room, licensing, €0, single-writer, exact-head and human-review rules remain in force.

## Autonomous PROGRESS acceptance

A provider's `PROGRESS` report is evidence only when all of these conditions hold:

- The report identifies the exact selected ledger task, and the PR body contains exactly one matching task-ID marker and one matching target-branch marker.
- A new PR has a non-empty diff. An existing PR must have a new head **and a different Git tree** from the pre-cycle head; an empty commit or metadata-only update is not progress.
- The PR is open, non-draft, unmerged, hosted in this repository and targets the selected `main` or `dev` branch.
- Required CI checks have completed successfully on the exact reported head SHA, from the GitHub Actions app.
- After CI polling, the validator fetches the PR again and rechecks its state, repository identity, base branch, task markers and exact current head. Any intervening change invalidates the report.

A validated `BLOCKED` report records a blocker and next action; it never counts as progress. These gates prevent stale heads, empty commits and unrelated PRs from satisfying the autonomous activation task.

- Shared Groq budget: 1,550 context tokens and 256 output tokens; caps verified context at 3,000 characters and task handoff at 1,100 characters.
